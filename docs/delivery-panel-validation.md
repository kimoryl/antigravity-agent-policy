## 实现范围

- 复用原 Python HTTP 服务、原 SQLite 文件，不增加第三方依赖。
- 五列交付看板、项目/任务类型筛选、目标/角色/阶段/步骤/更新时间/摘要卡片。
- 正式登记任务 ID、交付版本、实际路径、文件快照、检查报告及版本验收要求。
- 人工验收独立于执行状态，退回意见必填，旧版本或重复验收返回冲突。
- 修改或删除当前产物/报告使验收失效；重开归档旧执行记录，保留全部旧产物和意见。
- MCP `runtime_delivery` 与本地 CLI 提供 get/list/submit/reopen，验收仅在 Dashboard 进行。

## 浏览器完整流程

使用临时隔离数据目录 `$TEMP/delivery-preview`，验证完整交付审批状态机：

1. 提交 `交付说明.md` v1，面板显示待验收。
2. 点击退回但未填写意见时，显示必填提示。
3. 输入“请补充使用说明，写清楚查看产物和验收的操作步骤。”并点击退回，v1 进入需修改；原执行状态仍为 complete。
4. Codex 读取保存的意见，显式重开任务，重新规划、修改、检查并完成执行。
5. 提交 v2，面板再次进入待验收。
6. 在浏览器点击验收通过，v2 进入已验收。
7. 切换到 v1，仍能查看当时文件快照、退回意见和重开记录；旧版不显示验收按钮。
8. 项目与任务类型筛选分别生效；缺失文件明确显示“文件不存在”，验收通过按钮禁用；浏览器无前端错误日志。

该演示的通过结论仅用于验证交互，不代表用户已验收本次代码交付。安装缓存尚未更新；源码 Dashboard 可直接运行，新 MCP 接口在刷新插件并重启后加载。

## 设计边界

- 每次登记最多 30 个产物，单文件 64 MiB，交付总量 128 MiB；文件内容以 SQLite BLOB 保留历史。
- 文件必须位于任务项目目录内；没有文件系统任意路径读取接口。
- 看板每 15 秒刷新，验收动作也即时核对文件内容。HTML/SVG/脚本以纯文本查看，下载提供原始快照。
- 同一任务最新交付版本与任务修订号采用事务检查。SQLite 写事务将版本分配、文件登记及重开更新串行化。
- 无单独账号认证；沿用现有 loopback + 随机路径访问控制，并限制跨源验收请求。
